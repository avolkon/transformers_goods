# Архитектурная спецификация проекта (Технический дизайн)

**Проект:** MEPhI Product Title Subject Detection — NLP-пайплайн многоклассовой классификации русских названий товаров  
**Версия:** 1.0  
**Статус:** Утверждена (архитектурная проработка)  
**Источники:** `Разработка/ТЗ1_товары.md`, `Разработка/Правила_CompetitionRules.txt`, шаблон `Arch_TechDesign_PreditCure.txt`  
**Данные (локально):** `data/train.csv`, `data/test.csv`, `data/sample_submission.csv`  
**Соревнование:** [mephi-product-title-subject-detection](https://www.kaggle.com/competitions/mephi-product-title-subject-detection)

Документ описывает целевую архитектуру решения для курсового соревнования Kaggle и задания Яндекс Практикума: предсказание поля `subject` по тексту названия `text`. Учтены требования к воспроизводимости, обязательному Kaggle Notebook, метрике F1-macro, ограничениям на внешние данные и ИИ.

## Согласованные архитектурные решения

| Пункт / обсуждение | Утверждённая реализация | Обоснование |
|-------------------|--------------------------|-------------|
| Двойной артефакт сдачи | **Kaggle Notebook** (зачёт курса) + **CSV submission**; локальный репозиторий — источник воспроизводимости | Правила: без notebook с воспроизводимым submit зачёт по LB может быть нулевым |
| Метрика | **F1-macro** (`average="macro"`, `zero_division=0`) | Совпадает с Kaggle `kaggle_metric.py` и ТЗ |
| Пространство классов | Предсказание **только** из множества `subject`, встречающихся в `train.csv` | Тест не содержит новых меток; в локальных данных **341** уникальный класс (в ТЗ фигурирует также **371** — зафиксировать фактическое число при каждой загрузке данных) |
| Разделение train/val | **GroupKFold по нормализованному `text`** (одна группа = один уникальный title) | В train **23 563** строк-дубликатов названия при **~7 1xx** уникальных текстов; построчный split даёт утечку |
| Baseline | **TF-IDF (word + char n-grams)** + **LogisticRegression** / **LinearSVC (calibrated)** | Требование ТЗ/Kaggle: линейная модель на TF-IDF достаточна для допустимого submit |
| Целевая модель | Предобученный **русскоязычный encoder** (Hugging Face): приоритет `cointegrated/rubert-tiny2`, fallback `ai-forever/ruBert-base`, `deepvk/USER-bge-m3` (embedding + linear head) | Ожидаемый уровень курса «трансформеры»; разрешены HF-модели по правилам |
| Редкие классы | **140** классов с единственным примером в train (на момент локальной проверки) | F1-macro штрафует промахи по редким классам → class weights, weighted loss, без undersampling majority |
| Текстовая нормализация | Лёгкая: lower, `ё→е`, схлопывание пробелов; **без** лемматизации по умолчанию | Короткие названия (медиана длины **16** символов); агрессивная морфология может терять сигнал |
| Запрещённые подходы | Нет ручной/LLM-разметки test; нет prod-классификатора Naitii; нет платных private API на каталог | `Правила_CompetitionRules.txt`, Overview |
| Инструменты репозитория | **`uv`**, **`ruff`**, **`pytest`** (для `src/`), **Jupyter** / Kaggle kernel | Согласовано со шаблоном PredicCure; notebook — среда сдачи |
| Структура кода | Пакет `src/` (переиспользуемые модули) + `notebooks/` (EDA, Kaggle-экспорт) | Логика в `src/`, notebook тонкий orchestration layer |

## Общая архитектура

### 1. Контракты между компонентами

#### Контракт Data Loader → EDA / Training

```python
# Интерфейс загрузки данных (pandas)
interface DataLoader:
    def load_train() -> pd.DataFrame   # колонки: id, text, subject
    def load_test() -> pd.DataFrame    # колонки: id, text
    def load_sample() -> pd.DataFrame  # id, subject (шаблон сдачи)
    def get_label_space() -> list[str] # sorted unique subject из train
```

**Обязательные правила:**
- Загрузчик не меняет семантику полей; возвращает копии.
- Проверка: нет пересечения множества `text` между train и test (должно быть 0).
- Логирование: число строк, число классов, число unique text, число singleton-классов.

#### Контракт TextPreprocessor → FeatureBuilder / Tokenizer

```python
interface TextPreprocessor:
    def fit(df: pd.DataFrame) -> None          # опционально: словарь опечаток, частотности
    def transform(texts: Iterable[str]) -> list[str]
```

**Обязательные правила:**
- Одинаковые правила для train, val и test.
- Не использовать таргет `subject` в transform.
- Сохраняемый артефакт: `artifacts/text_preprocessor.pkl` или JSON-конфиг.

#### Контракт FeatureBuilder (TF-IDF ветка)

```python
interface TfidfFeatureBuilder:
    def fit(texts: list[str], y: np.ndarray | None) -> None
    def transform(texts: list[str]) -> sparse matrix
    def save(path) / load(path)
```

**Обязательные правила:**
- `fit` только на train fold / полном train.
- Комбинация word (1–2) и char (3–5) n-grams — конфигурируемо.
- `max_features`, `min_df` задаются в `Config`.

#### Контракт EncoderModel (Transformer ветка)

```python
interface EncoderClassifier:
    def fit(train_loader, val_loader, label2id: dict) -> None
    def predict(texts: list[str]) -> list[str]   # строки subject
    def predict_proba(texts) -> np.ndarray     # optional
    def save(path) / load(path)
```

**Обязательные правила:**
- Токенизация через `AutoTokenizer` той же модели.
- `max_length` (например 64–128) с truncation; padding batch.
- Loss: `CrossEntropyLoss` с `weight` по частоте классов (inverse freq или effective number).
- Early stopping по **macro-F1** на validation (не accuracy).

#### Контракт Validator → Model Selection

```python
interface GroupTextKFold:
    def split(df: pd.DataFrame, n_splits=5) -> Iterable[tuple[np.ndarray, np.ndarray]]
    # Индексы строк train_df; группировка по hash(normalize(text))
```

**Обязательные правила:**
- В одном fold не допускаются две строки с одним и тем же нормализованным `text`.
- Для стратификации по классу при группировке: **StratifiedGroupKFold** (sklearn ≥1.3) или ручной баланс при assign групп.

#### Контракт Predictor → Submission

```python
interface SubmissionWriter:
    def build(test_df: pd.DataFrame, subjects: list[str]) -> pd.DataFrame
    def validate(submission: pd.DataFrame, test_df, label_space) -> None
    def write_csv(path: Path) -> None
```

**Обязательные правила:**
- Строк ровно столько, сколько в `test.csv`; множество `id` совпадает.
- Значения `subject` ∈ label_space.
- Заголовок: `id,subject` (как `sample_submission.csv`).

### Чеклист Kaggle Notebook (Правила_CompetitionRules.txt, п. 8, строки 20–25)

Чтобы получить **зачёт по курсу**, недостаточно одного CSV на leaderboard. Нужны **оба** артефакта: **Submission (CSV)** и **опубликованный Kaggle Notebook**, привязанный к соревнованию (или kernel, доступный преподавателю).

**Соответствие формулировкам правил:**

| Формулировка правила | Что сделать в notebook |
|----------------------|-------------------------|
| *runs top to bottom without manual edits* | После публикации проверить **Cell → Run All** (или «Run all») на чистой сессии: без правок ячеек между запусками, без «догоняющих» ручных `fit` только на одной ячейке. Зафиксировать `random.seed` / `np.random.seed` / `torch.manual_seed`. |
| *loads train.csv / test.csv* | Явное чтение из input соревнования, например `pd.read_csv("/kaggle/input/mephi-product-title-subject-detection/train.csv")` (путь сверить с Data tab). |
| *short baseline → valid submission (example submit)* | Отдельный блок **Baseline**: простая модель (минимум TF-IDF + линейный классификатор), обучение на train, предсказание на test, запись **`/kaggle/working/baseline_submission.csv`** с колонками `id,subject` и **2046** строк (как в test). |
| *actual model → writes the file you submitted* | Следующий блок **Final model**: ваша основная модель (encoder и т.п.), та же схема сдачи. Итоговый файл **`/kaggle/working/submission.csv`** (или одно согласованное имя) должен **совпадать по логике** с файлом, который вы загружаете в **Submit Predictions** на Kaggle (те же id, формат; при полном перезапуске notebook содержимое воспроизводится). В markdown указать: «этот файл соответствует моему сабмиту от ДД.ММ». |
| *readable (no huge dumped logs, no secrets)* | Короткие `print` / `display`, без `print(df)` на 30k строк; `logging` с уровнем INFO; **без** токенов, API keys, путей к приватным данным. Убрать отладочные ячейки или пометить как optional и не ломающие Run All. |

**Риск при несоблюдении:** если notebook отсутствует или **не воспроизводит** выбранный финальный submit, результат на leaderboard для курса **может быть обнулён**, даже если Kaggle принял CSV (см. тот же файл правил, абзац после п. 8).

**Рекомендуемый порядок ячеек (шаблон):**

1. **Метаданные** — заголовок, соревнование, автор, дата; цель (subject classification, F1-macro).
2. **Зависимости** — `%pip install …` только то, что нужно; версии пинить при нестабильности.
3. **Константы** — `SEED`, пути `TRAIN_PATH`, `TEST_PATH`, `BASELINE_OUT`, `SUBMIT_OUT`.
4. **Загрузка данных** — train, test, sample_submission; assert размеров и колонок.
5. **Мини-EDA** (кратко) — число классов, длина текста (для отчёта Практикума).
6. **Baseline (обязательно)** — препроцессинг → fit → predict test → `to_csv(BASELINE_OUT, index=False)` → assert `id` ⊆ test.id.
7. **Валидация / CV** (по желанию, компактно) — macro-F1 на group split, без огромных матриц в stdout.
8. **Final model (обязательно)** — обучение → predict → `to_csv(SUBMIT_OUT, index=False)`.
9. **Проверка submission** — сравнение с `sample_submission` (shape, dtypes, уникальность id, все `subject` из train).
10. **Итог** — одна ячейка: путь к файлу для скачивания / Submit; напоминание, что этот файл загружен на Kaggle.

## Риски и митигации

| Риск | Митигация |
|------|-----------|
| Утечка при CV из-за дубликатов `text` | Group split по text |
| Низкий macro-F1 из-за singleton-классов | class weights; не удалять редкие классы; анализ ошибок |
| Notebook не воспроизводит submit | Один источник истины: те же seed, те же веса, assert hash файла |
| Дисквалификация за LLM на test | Только модель, обученная на train; запрет ручной правки test labels |
| Различие 341 vs 371 классов в документации | Пересчитывать `n_classes` при загрузке; не хардкодить 371 |
| Ограничение RAM/ GPU на Kaggle | tiny-BERT, gradient accumulation, меньший batch |

## Итоговое архитектурное решение

Архитектура согласована с `ТЗ1_товары.md` и `Правила_CompetitionRules.txt`.

**Обязательные инварианты:**

1. Метрика оптимизации и отчёта — **F1-macro**.
2. Валидация — **по группам `text`**, не по строкам.
3. Класс предсказания — **только из train label space**.
4. Сдача курса — **CSV + воспроизводимый Kaggle Notebook** с baseline и финальной моделью.
5. Запрещены prod/Naitii классификатор и LLM-разметка test без обученной модели.
6. Разрешены **публичные HF-модели** и открытые библиотеки.
7. Код слоистый: **data → text → features/models → validation → inference**.
8. Зависимости — **`uv`**; локальный запуск и путь в notebook документированы.
9. Baseline TF-IDF **обязателен** как минимум в notebook.
10. Перед submit — **валидация схемы** submission.
