# Ревью baseline и linear_v2

Дата: 2026-11-22

## Почему public 0.87394 «низкий», а CV ~0.47

Group-CV по `text` бьёт **macro-F1**: 140 классов с 1 примером дают F1=0, если попали в val. Public LB (~30% теста) такие классы может почти не содержать — поэтому CV и LB не совпадают по абсолюту, но **ранжирование моделей** на holdout всё равно полезно.

## Почему encoder_v1 бесполезен (eval F1 0.006)

- `rubert-tiny2` + **2 эпохи** на 341 класс: голова не успевает.
- Inverse-frequency веса для singleton раздували loss.
- Локально нет CUDA — base-модель не прогнать за разумное время.

Исправлено в коде (sqrt-weights, padding collator), но **сабмит encoder не для Kaggle**.

## Файнтюнинг линейных моделей (один group-holdout, seed=42)

| Модель | holdout macro-F1 |
|--------|------------------|
| LogReg baseline (сдано, LB 0.87394) | 0.519 |
| LinearSVC C=1, char 2–6, min_df=1, unique_text | 0.567 |
| LinearSVC word 1–3 | 0.559 |
| Ridge unique | 0.558 |
| LinearSVC / SGD на всех 31k строках | ~0.40 |

**Вывод:** дубликаты названий вредят (перекос на частые классы). LinearSVC + более широкие char-n-grams лучше LogReg.

Сетка C: 0.25→0.553 … **C=3.0 → 0.570** (лучший).
