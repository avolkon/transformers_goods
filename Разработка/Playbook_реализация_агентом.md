## 1. Как вести разработку

| Принцип | Практика |
|--------|----------|
| Воспроизводимость | `random_state=42`, версии зависимостей, один способ получить `FIT` |
| Код vs ноутбук | Логика в **`src/` + `scripts/`**; ноутбук — загрузка, EDA, вызов пайплайнов, выводы |
| Два контура оценки | **Офлайн:** group-CV / 3-fold на unique text; **онлайн:** public LB |
| Не путать метрики | **macro-F1 на FIT после fit** ≈ переобучение; для отчёта — **CV** и **LB** |
| Сабмиты осмысленно | ≤5/день, 2 final; каждый эксперимент — `submissions/<name>/meta.json` |
| Документация по ходу | После каждого этапа — **markdown-вывод** в ноутбуке, не в конце |

Порядок: **EDA → baseline (сабмит) → сравнение/тюнинг → финал (сабмит) → ноутбук → архив в git**.

## 3. Какой результат получить первым

**Цель этапа 1 (1–2 дня):** не «лучший score», а **замкнутый контур**:

1. `normalize_text` → колонка `text_norm`.
2. Обучение на **`FIT`** = одна строка на уникальный `text_norm` (дубликаты в train не раздувать).
3. **TF-IDF (word 1–2 + char 3–5) + LogisticRegression**, `class_weight='balanced'`.
4. Предсказание на **весь test** → **`baseline_submission.csv`**: 2046 строк, только `id, subject`, все `subject` ∈ train.
5. Один **сабмит на Kaggle** → зафиксировать **public score** (ориентир ~0.87).

**Критерий готовности:** скрипт/ноутбук повторяет тот же CSV; `validate_submission()` без ошибок.

## 4. EDA (под критерий «комплексный анализ»)

Одномодальная задача: «признак» = **текст**. В ноутбуке **§2–§3** с **print + 1–2 графика** и **markdown-выводом**.

**Обязательный минимум:**

| Блок | Что сделать | Зачем для модели |
|------|-------------|------------------|
| Пропуски | `isna()`, пустой `text` | Обосновать imputation / нормализацию |
| Объём | строк train/test, число классов | Масштаб задачи |
| Дубликаты | unique `text_norm` vs строк train | Решение **FIT** |
| Классы | singleton-классы, топ-5, гистограмма «примеров на класс» (log Y) | macro-F1, `class_weight` |
| Длина текста | median, p95, p99, гистограмма | «выбросы» = длинные названия, без обрезки |
| Утечки | raw text train∩test | Доверие к offline/LB |
| Признаки | `id` / `subject` не в модель; только `text_norm` | «нерелевантные признаки» |
| Корреляции | Явно: нет числовой матрицы признаков | NLP-постановка |

**Вывод EDA (markdown):** дисбаланс, дубликаты → **FIT**; редкие классы → риск F1=0 на macro; короткий текст → TF-IDF + char n-grams.

## 5. Выбор и сравнение моделей

**Минимум для критерия 2:** **две модели** + **метрики**.

| Этап | Модель A | Модель B |
|------|----------|----------|
| Example | LogReg + TF-IDF (baseline) | — |
| Финал | — | LinearSVC + расширенный TF-IDF |

**Сравнивать на одних и тех же данных:**

- **3-fold StratifiedKFold** на **FIT**, `scoring='f1_macro'`.
- **macro-F1 на FIT** после fit (с пометкой «завышено»).
- **Public LB** после сабмита.
- На test без меток: **% совпадения предсказаний**, число **уникальных классов** в pred.

**Таблица в ноутбуке (§6.1 + markdown):**

| Модель | CV macro-F1 | macro-F1 FIT | Public LB | уник. классов test |

**Что не считать «лучшей» без данных:** только FIT-F1 или только «красивая» теория.

## 6. Обучение и файнтюнинг

### 6.1 Baseline (зафиксировать)

- `min_df=2`, char (3, 5), 80k/80k, LogReg `C=2`.
- Fit на **FIT**, predict test → `baseline_submission.csv`.

### 6.2 Улучшение (локально в `scripts/`)

Перебор **не в ноутбуке**, а в скриптах с логом:

- unique text vs all rows (гипотеза: all rows **хуже** ~0.40 vs ~0.52–0.57).
- char (2, 6), `min_df=1`, max_features 120k/150k.
- **LinearSVC**, сетка **C** (0.25 … 3).
- Разбивка **group / holdout по unique text**, не случайный shuffle строк.

**Выигрышная конфигурация (пример):** LinearSVC `C=3`, char 2–6, `min_df=1`, FIT.

### 6.3 Encoder (опционально)

Только если есть **GPU** и время; иначе в отчёте: «пробовали / отказ с обоснованием». Не сабмитить F1≈0.

### 6.4 Файнтюнинг — правила

- Одна ось за раз (C, n-grams, min_df, clf).
- Фиксировать **seed** и **набор строк (FIT)**.
- После сетки — **один** финальный сабмит + сохранение `submission.csv` в `submissions/linear_v2/`.

## 7. Обоснование лучшей модели (по данным)

1. **Постановка:** 341 класс, короткий русский текст, macro-F1.
2. **Ограничение данных:** median 1 пример на класс в FIT → потолок по редким классам.
3. **Офлайн:** CV финала **выше** baseline (пример: 0.520 vs 0.466).
4. **Онлайн:** public LB финала **выше** baseline (пример: 0.90084 vs 0.87394).
5. **Связь изменений:** ~6% других предсказаний; примеры близких и плохих ошибок.
6. **Честные минусы:** ~0.999 на FIT = переобучение; меньше уникальных классов на test; невызванные классы.
7. **Решение:** финал = **сабмит**, baseline = **example** по правилам курса.

Формулировки в духе **гипотезы до прогона** для методички; **факты** — из ячейки сравнения и скрина LB.
