## Шаги

- [ ] **1. Данные на месте.** Проверить `project2/data/`: `train.csv`, `test.csv`, `sample_submission.csv`, `vocabs.json`. Если файла нет — остановиться и написать в чат. Самому с Kaggle не скачивать.
- [ ] **2. Схема.** Сверить и записать в `Разработка/p2/Проверка_данных.md`:
  - train 22654, test 400, sample 400;
  - колонки `id,title,description` и `id,colors,materials,length,size`;
  - пересечение `id` train∩test = 0;
  - ключи `vocabs.json`, размер каждого списка, 5 примеров на слот.
- [ ] **3. Скелет каталогов** в `project2/`: `src/product_ner/`, `scripts/`, `tests/`, `notebooks/`, `submissions/baseline/`, `pyproject.toml`. Пути от корня `project2`, `RANDOM_STATE = 42`.
- [ ] **4. Контракты, без модели p1.** Перенести идеи, не файлы классификатора:
  - `text.py` — lower, `ё→е`, схлопывание пробелов;
  - `data.py` — чтение четырёх файлов;
  - `submission.py` — 400 строк, те же `id`, пять колонок, ячейки как JSON-списки, каждое значение из своего списка vocab;
  - `gazetteer.py` — longest match по словарю, слот без попадания → `[]`.
- [ ] **5. Правило матчера после шага 2.** Зафиксировать в `meta.json`, не в отдельном исследовании: ищем в `title` и `description`; сначала более длинная строка vocab; регистр и `ё/е` не различаем. Конвертер единиц («100 см» ↔ «1 м») не писать, пока примеры vocab не показывают, что канон — другая единица.
- [ ] **6. Тест проверки CSV.** `tests/`: образец проходит; чужая колонка, чужой `id`, значение не из vocab, битый JSON — падают.
- [ ] **7. Прогон.** `python project2/scripts/run_baseline.py` пишет:
  - `project2/submissions/baseline/baseline_submission.csv`
  - `project2/submissions/baseline/meta.json` (seed, правило матчера, sha256, доли непустых слотов).
- [ ] **8. Первая проверка, локально.** Скрипт и тест должны закончиться без ошибки. В чат — только сводка:
  - число строк = 400, id совпали с test;
  - доля непустых `colors` / `materials` / `length` / `size`;
  - 5 строк CSV;
  - подтверждение, что не все 400 строк состоят из четырёх `[]`.
